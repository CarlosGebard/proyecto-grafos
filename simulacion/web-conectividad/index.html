Cómo se aplicó el algoritmo

Cuatro fases sobre los datos reales del escenario cargado. Toca una fase para verla en el mapa; debajo, el modelo matemático y el archivo real que produce cada uno de sus elementos.

Formulación matemática

Cobertura máxima ponderada con red conectada: la variante ponderada (i) de PartialConRBDS, resuelta de forma exacta bajo el régimen Δ(Gconn) acotado. El goloso es sólo baseline de contraste.

max f(S) = Σd ∈ U(S) w(d) con U(S) = ∪a ∈ S C(a)
s.a. |S| ≤ k
Gconn[S] conexo (una sola red)
S ∩ G ≠ ∅ (sólo si se exigen gateways)
empate ⇒ S lexicográficamente menor (reproducible)
C(a): (a,d) ∈ Ecov ⇔ dist(a,d) ≤ ρ(a) ∧ LOS(a,d)
Econn: (u,v) ∈ Econn ⇔ dist(u,v) ≤ min(ρu, ρv) ∧ LOS(u,v)

Cómo lo resuelve el motor exacto

  1. Enumeración canónica (ESU, Wernicke 2006). Cada subconjunto conexo de tamaño ≤ k se genera exactamente una vez, anclado en su vértice mínimo; las extensiones usan el vecindario exclusivo N(a) ∖ N(S) con id mayor que la raíz.
  2. Unión incremental del objetivo. Contadores cover[d] por localidad: al entrar una antena, f suma sólo la población que «estrena», así la unión nunca cuenta dos veces la misma localidad.
  3. Cota de prefijos. Una rama se poda sólo si su mayoración queda estrictamente bajo el mejor f hallado; podar por empate rompería el desempate lexicográfico.
  4. Desempate lexicográfico. Ante empate en f gana la tupla de identificadores menor: el mismo resultado en cualquier máquina.
  5. Requisitos duros. Gateway exigido (S ∩ G ≠ ∅) y presupuesto max_evaluations: si el peor caso excede el presupuesto, el motor aborta con ExactLimitExceeded en vez de devolver una solución no óptima.
